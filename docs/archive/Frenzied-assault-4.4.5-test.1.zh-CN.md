# 狂暴攻势 1.4.0 · HCM 4.4.5-test.1

这是动画同步测试版，仅生成 release，未改动游戏安装、Vortex 模组目录或现用 AppData 词条包。

## 本次调整

| 项目 | 本版效果 |
| --- | --- |
| 全部敌人移速 | +30%，杂兵、精英、特感与 Boss 使用相同增幅 |
| 走路与跑步 | 步频与移动增幅同步；起步和转向动画的配套时机同步调整 |
| 近战与远程攻速 | +40%；其他原版攻速增益仍参与数值计算 |
| 攻击过程 | 前摇、命中、投掷、收招与动画使用同一比例，取消旧版前摇单独减半 |
| 变种人 | 独立冲锋速度路径加入移速增幅；按实际冲锋速度匹配步频，包括叠加毒气的情况 |
| 抓取与抛掷 | 变种人的抓取、连续砸击、抛掷与对应受控玩家动画使用配套时机 |
| 受击反应 | 删除 90% 硬直缩短；普通受击、撞墙眩晕及空中受击反应保持原版时长 |
| 出手等待 | 保留攻击冷却缩短 80% 和解除围攻配额等待 |

射程、视线、目标锁定、伤害、手雷飞行与毒气寿命保持原有规则。移速增幅不直接改写空中抛物线和受外力推动的速度。

## 动画同步方式与边界

旧版仅缩短部分动作计时，没有同步控制动画播放进度，可能出现伤害或抛掷早于画面的情况。本版使用游戏本身的动画层时间读写接口，校正本地主机看到的动画进度。移动按 1.3 倍、攻击按对应攻速处理，状态切换、动画重新开始、暂停、任务退出和受击中断分别处理。缓存会重复使用，死亡单位会从动画跟踪中移除。

近战原版仅对收招额外应用攻速，本版避免这一段再次缩短动作。其他攻速词条叠加后，同一次攻击的前摇、命中、收招与画面共用同一个速度；增益变化在新动作开始时重新取值。

原版已经存在的变种人步频上限会让高移速冲锋滑步。本版根据实际目标冲锋速度补偿步频，普通导航与直接速度路径各加一次 30%，不会对同一路径重复叠加。

**本版尚未进行游戏内视觉验收。** 自动检查使用原版 Lua 方法，但引擎的骨骼动画、根运动、动画事件与音效仍由测试替身提供。逐帧时间校正属于播放位置调整，不能仅凭离线通过就保证所有素材的混合、循环边界、声音事件与碰撞观感完全正确。发布为测试版正是为了明确这一验证边界。

动画校正目前限于本地主机。没有增加向远程玩家发送动画时钟的网络协议，因此不宣称远程客户端已全部同步。玩家自由行动时不会获得敌人的动画速度；只有仍被对应敌人实际控制的配对动作才参与校正。

## 已覆盖的检查

- 运行原版近战动作，检查 +40% 时命中点与总时长共同缩短，并检查其他近战攻速增益叠加后不会重复缩短收招。
- 运行两类掷弹兵共八种普通与快速投掷，检查投出、特效、收招和显式或默认冷却；不修改共享原版数据。
- 运行原版变种人冲锋计算与运动接口，检查基础 8–12 速度变为 10.4–15.6；毒气另加 30% 时变为 13.52–20.28，并检查对应步频比例。
- 使用原版变种人动作配置运行抓取、三段砸击伤害与抛掷准备；验证伤害在相应动画标记时机发生。
- 运行原版走路、跑步状态切换与导航限速方法，检查步频、起步计时和实际速度使用相同的 1.3 倍比例。
- 运行原版受击动作，验证硬直时长、重复受击与退出时机保持原版。
- 使用原版世界更新入口检查模拟的动画层进度、空层、切换、循环、暂停、配对玩家释放、不同世界与非房主路径。
- 保留销毁与替换运动组件、临时向量跨帧、异常后恢复共享数据、任务清理和重复进入任务的检查。

这些检查不提供实测帧率或游戏内画面结论。

## 安装与核对

1. 手动安装本 release。
2. 打开「DIY 管理」，点击「解压模板DIY词条」，将外部狂暴攻势更新到 **1.4.0**。此按钮会覆盖所有同名模板包，并保留旧包备份；勾选状态使用原有稳定标识。
3. 重新启动游戏，再开启一局选择了「狂暴攻势」的任务。

日志中的 `Frenzied assault 1.4.0` 表示新版脚本已激活；首次出现 `animation_clock=running` 表示本局已经执行动画层时间校正。这两项证明代码路径开始运行，不能代替实际画面检查。

实机重点观察走跑切换有无滑步、挥击画面与伤害是否重合、掷弹兵手雷是否在脱手时生成，以及变种人抓取、砸击、抛人和撞墙硬直是否自然。若仍有异常，可以保留该局日志继续定位。
