# 爆破手停顿、混合动作与刷新缓存

2026-09-12，HCM 4.4.6-test.13 / 狂暴攻势 1.7.3。源码核验仍基于游戏 1.12.5、提交 `0f0cb45991e9305ef4a7b925370792d7d6035f95`。

## 爆破手为何扑完才停顿自爆

原版 `BtPoxwalkerBomberApproachAction` 同时负责接近目标和扑击，实际攻击计时藏在移动动作里。旧版将它归为移动，只加快动画，没有修改其中的扑击截止时间。原版 `_start_lunge` 设置约 1.222 秒的扑击结束时间和约 0.667 秒的目标追踪窗口；`_update_lunge` 到结束时点直接触发自身死亡，随后 `BtChaosPoxwalkerExplodeAction.enter` 生成爆炸，本身没有额外等待。

所以问题不是爆炸入口又多等了一次：动画按两倍速度推进，动作结束仍等原来的时点。现在这两个时长减为约 0.611 秒、0.333 秒，原版机器人危险提示也从同一数据读取而同步缩短。保留 `fuse_timer=1.5` 的兜底引信及被推开／打断分支；不能把正常扑击结束与防御打断后的引信混为一谈。

同时复现了重复位移加速：扑击从加速后的动画位移计算速度，导航又乘了一次词条倍率。现在仅在这种阶段撤下本词条的导航修正，普通移动恢复时再加回。其他来源的导航倍率保留。使用现有 AI 回调，在状态边界更改一次，不增加挂接或内存轮询。

## 同类逻辑检查

| 动作 | 修正或保留方式 |
|---|---|
| 爆破手接近／扑击 | 只缩短扑击结束和移动窗口；兜底引信、被推开与受击规则原样保留 |
| 掩体攻击 | 探身、瞄准及开始瞄准时点同步缩短；读取实际枪械倍率，进入掩体及受压制阶段保持原速 |
| 通用冲刺 | 准备、定向转身、对应转向时点与收招同步；动画驱动阶段移除重复导航倍率，冲刺常规导航保留两倍速度 |
| 喷火巡逻 | 瞄准、扫射推进、对应结束与火焰到达速度同步；火焰区域寿命和巡逻等待保持原版 |
| 跑动受击 | 原版字段是 `stagger_duration`，补上该字段检查，受击阶段不再误加速 |
| 纳垢兽对齐 | 原版处于 idle／动画驱动转向，原有保护有效，保持原版时长与动画 |
| 不规则追击跳步 | 原版动画驱动跳步已有保护，保留其几何与持续时间 |
| 喷火兵最短移动、巡逻等待、逃跑／冲刺导航超时 | 属于行为选择或兜底边界，保留原版，不笼统缩短所有时间字段 |
| 出门、开门、跨障碍 | 保留上一版的原生位置约束与导航交接 |

混合动作通过各自明确的字段表生成缓存副本，不递归放大无关伤害、距离或导航数据。扫描范围及引用字段记录在 `build/checks/frenzied-mixed-log-audit.json`。这些检查不能等同于所有地图、单位与 Buff 组合均已完成实机验证。

## 刷新前清理缓存

点击刷新、导入已安装词条或解压模板时，先丢弃派生快照。磁盘内容重新读取、校验、组合；即使内容哈希相同，也重新生成已解析词条、来源与哈希表，避免沿用被修改的内存对象。成功前保留上一份已发布数据，读取失败会显示错误，不会直接把列表清空。选择设置保留。

大厅刷新先结束旧引擎回调和动作状态，再清理包内模块、加载失败记录、来源、效果读取及资源缓存，随后加载新内容。旧资源监听被取消，迟到的加载结果不会覆盖下一批缓存。任务中刷新只失效可重建的效果读取缓存，并更新下一局的库；当前任务使用独立快照，避免一半旧计时、一半新动画。任务结束后，旧脚本缓存被明确释放。

不会清空全局游戏模块或卸载仍被原生入口引用的辅助库。原生辅助库、ABI、动画和内存读取实现与 1.7.2 保持一致，上一版区域缓存修正保留。

本轮日志为 `console-2026-09-12-12.43.29-3995dce0-2d7c-4332-82b0-38ea09de6327.log`。第 1889 行确认加载 1.7.2，第 2457 行确认原生动画加速实际执行。18 个采样窗口中，内存查询次数与已验证区域数一致，说明没有再按每个单位的页面重复查询。

排除加载窗口后，动画准备按采样数加权平均 0.819 毫秒；最慢窗口平均 1.383 毫秒，单次最高 2.656 毫秒。上一场最高为 8.742 毫秒，但两场敌人、场景和触发不同，不能直接换算为严格的 FPS 提升比例。

日志仍有四次 ledges／ledges_with_fence 导航释放失败，集中在约 `(210, -92, 2)` 附近；本次未看到上一场的 doors 释放失败，但这不证明该门已在相同条件下通过。增益事件池有 25 条警告记录，其中汇总拒绝 5445 个额外事件，说明战斗触发压力仍然存在。它们不是爆破手单次扑击的计时记录，也不足以认定某一个 Buff 就是全部剩余低帧的原因。
