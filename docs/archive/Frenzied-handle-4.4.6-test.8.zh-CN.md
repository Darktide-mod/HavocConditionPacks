# 狂暴攻势 1.6.5：动画全部失效的原因与修复

本次交付两个独立更新：HavocConditionManager 4.4.6-test.8（狂暴攻势包 1.6.5），以及 MortisBuffManager 4.6.2。只安装其中一个 ZIP 不会更新另一个模组。未改动游戏 mods、Vortex 或 AppData 实例。

## 日志确认

读取 `console-2026-09-12-09.12.09-4c5d54b8-cb0a-4578-92b5-f64d2f33598d.log`，共 68 条狂暴攻势动画失败记录，全部为 `reason=invalid unit reference`，成功记录为 0。猎犬、枪手、普通步兵、狙击手、变种人及其攻击／移动路径都被拒绝。

日志同时确认载入的是狂暴攻势 1.6.4。枪械和近战时序仍有诊断输出，说明失效位于动画桥接的单位校验阶段，动画函数尚未执行；不是所有加成一起失效，也没有证据表明本次是游戏版本签名不匹配。

## 代码错误

上一版假设单位句柄必须是低两位为零、整体小于 2³² 的指针值；不满足就退出。该假设比实际引擎的读取规则更严格。

已核验的 `Unit.animation_get_time` 在首选地址 `0x1405390f7` 开始执行 `mov rcx,rax; shr ecx,2`：使用低 32 位，移除两位标记，再从剩余位解出索引和代数，查询当前单位表。非零高位和标记位并不应在这里被拒绝。

1.6.5 按这条规则解码，并在截断前一直保留 cdata，避免把完整 64 位值先转成 Lua 浮点数造成精度丢失。保留执行文件、函数签名、单位代数、内存范围、层布局和读回校验，没有通过关闭整套校验来绕过错误。

日志没有打印原始句柄，因此仅凭日志不能区分每个单位具体触发了旧检查中的哪一条。修复覆盖了该检查与引擎实际规则的差异，并分别测试各类标记与真实 Lua lightuserdata。

## 验证边界

- 从已发布 ZIP 提取原版 1.6.4 动画桥接，复现带标记、高位值及真实 Lua lightuserdata 被拒绝、内部函数调用次数为零的行为。
- 新代码在同一隔离内存布局下接受相同的合法索引／代数，并能推进模拟播放层；无效索引、过期代数、无效内存和读回失败仍拒绝。
- 保留原位混合、原生事件边界、跨障碍流程与 +100% 测试值的既有检查。仍只支持已经核验的 Windows 游戏 1.12.5 执行文件。
- 离线测试不执行真实游戏内部动画函数。实机骨骼画面、音效／事件节奏、根运动和性能尚未验证。

## 更新确认

安装 HCM 4.4.6-test.8 后，在大厅更新／解压外部「狂暴攻势」包至 1.6.5，再进入新任务。任务日志应包含 `Frenzied assault 1.6.5` 和 `unit_ref=low32_shift2`；包文件按任务重新读取，不必为纯 Lua 词条包更新退出进程。

核查时本机 MortisBuffManager 是 4.6.0，仍为旧天赋页。必须另外安装 MortisBuffManager 4.6.2，才能加载四分类、流派筛选与预选移除、滚轮浏览和离开页面后的绘制拦截。主模组 UI 代码需在模组重新加载后生效，不能用刷新 DIY 包替代。
