# 狂暴攻势 1.6.4：固定片段与混合动画修复

对应 HavocConditionManager 4.4.6-test.7。仅生成发布文件，未部署到游戏、AppData 或 Vortex。离线回归通过；没有执行实机动画、事件节奏、性能或联机画面验收。

## 已查明的原因

此前检查了 50 个 minion 定义和 26 种状态机资源。17 个定义对应的资源虽然含 `anim_move_speed` 变量，却没有表达式读取它；两个掷弹兵还没有在动画扩展中注册该变量。猎犬三种变体共用的状态机中，慢走使用该变量，战斗奔跑则是速度固定为 1 的三片段混合。仅写入变量不能覆盖这些情况。

旧攻击动画使用 `set_time → set_animation → set_state`。引擎会重建播放层、清掉正在进行的混合；混合节点的动画选择索引通常为 -1，恢复路径还会忽略其时间。这分别解释了过渡突兀和部分层仍保持原速。

完整资源记录见项目 `docs/Frenzied-movement-coverage-20260912.zh-CN.md` 与 JSON。这是对旧版的审计，不能解读为新版已经逐单位完成实机验收。

## 本次实现

- 通过 LuaJIT FFI 调用引擎现有的 AnimationInstance 原位推进函数。目标是正在播放的层，其真实混合节点和子播放器由引擎处理；不猜测 crossfade handle，不重新选择片段，不重建动画层，也不修改可执行文件。
- 移动和攻击共用此路径，不再依赖兵种是否注册或使用 `anim_move_speed`。删除两个移动变量 Hook 和一个错误抵消导航倍率的 Hook，保留其他原生加成。
- 只在所属任务世界的动画求值前操作；暂停、非房主、死亡、其他世界和任务清理后不推进。先观测原生时间速率，再补充加速量；切换状态或片段时重新观测，不把旧时间带进新动作。
- 不越过下一项原生动画事件或片段终点，让正常动画求值处理事件与状态转换。边界附近的实际倍率会短暂低于目标值，因此不能把它描述成每个事件都严格等比快放。
- 原生起步的根运动区间、停止、转向、受击与跨障碍动作保持原生处理。攀爬、翻越、跨沟、下落和落地保留原有时序、XYZ 轨迹与导航控制释放。
- 常规移速、枪械、近战和特殊动作继续使用 +100% 测试值。攻击根运动补偿与碰撞检测沿用已覆盖的路径；片段结束和事件附近的配合效果仍需实机观察。
- 对同一兵种／动作只记录一次成功与一次失败。时间推进失败的同一状态／片段暂停尝试，进入不同状态或片段后再检查。

## 引擎兼容边界

这不是公开且跨版本稳定的 Lua API。本次仅核验本机 Windows x64 游戏 1.12.5 的执行文件：

- 文件 SHA-256：`e0f581d2c63b692c7d9f328e3edeb39c0f484956905569d38ba27bbb3fcc0aae`。
- PE 时间戳：1786450566；映像大小：41992192。
- 相对模块地址：原位推进函数 RVA `0x5a2460`；256 字节完整签名；同时检查单位查询、动画实例查询和子播放器推进函数的代码签名。
- 从运行时模块基址计算地址以适配 ASLR，不使用固定进程绝对地址。
- 每次操作核对 UnitRef 代数、可读内存范围、层数、实时钟、原生事件游标与布局；操作后检查实时钟及公开 API 的时间／状态／片段读回。

游戏更新或代码签名不匹配时，中止自定义 Hook 激活并记录错误，不回退到无保护调用。该拒绝针对本包的自定义动作和动画 Hook；DIY 管理器已经选中的声明式基础 stat 加成不由此接口撤回。不能把兼容拒绝误认为整个词条被移出选择。

## 检查与实机验收范围

已通过的离线检查包括：

1. 独立内存中的 UnitRef、实例布局、真实 Windows 查询接口、函数签名、错误代数、失效指针、事件／终点边界和读回失败；测试使用调用替身，没有执行游戏内部函数。
2. 固定速度的掷弹兵片段、猎犬混合奔跑（选择索引 -1）、慢走、原生起步、停止和混合窗口的动画边界替身；真实动画同步 Lua 在原生 ScriptWorld 调用顺序下运行。
3. 374 个原生近战事件、8 个原生投弹流程、变种人冲锋与毒气倍率、抓取／三次砸击／投掷，以及枪械首发、警示特效、点射间隔与冷却。
4. 原生攀爬、围栏、跨沟、下落／落地、终点落位和导航控制释放。
5. 真实 DIY 加载器与 DMF Hook 注册表中的 1.6.1／1.6.3 → 1.6.4 更新、同版本文件修改、旧 Hook 停用、清理与重复任务，不叠加导航倍率。

实机尚需观察：两种掷弹兵移动，三种猎犬的奔跑／转弯／扑咬，其他固定速度单位的移动与攻击，起停连续性、跨障碍和动画事件是否完整；高密度场景的帧耗时及其他玩家画面未验证。日志中的 `method=in_place` 和 `animation_clock=verified` 只代表实时钟、状态与片段检查通过，不单独证明所有骨骼、音效和根运动结果正确。

## 更新方式

安装本次 ZIP 后返回大厅，更新或解压「狂暴攻势」外部 DIY 模板包，再开始下一局。新包有 `lua/native_clock.lua` 文件，包版本应显示 1.6.4。Lua 包及相对依赖模块按新任务重新加载，无需退出游戏；不在正在进行的攻击或翻越过程中更换本包 Hook。

成功激活日志包含 `Frenzied assault 1.6.4`、`movement_animation=in_place`、`attack_animation=in_place`。各兵种日志带 `unit_action`；若出现 `signature mismatch`、`unsupported game executable` 或 `animation_clock=failed`，应按该原因复核，而不是仅凭导航速度判断动画已修复。
