# 狂暴攻势 1.6.0：全部提速 100% 测试版

随 HavocConditionManager 4.4.6-test.3 发布，只生成 release，不部署当前游戏、Vortex 或 AppData 词条。

## 日志结论

2026-09-12 13:47 启动的会话加载了管理器 4.4.6-test.2，但首局仍使用此前解压的词条包 1.4.0。其激活日志为 move=1.30、attack=+0.40，并出现 animation_clock=running。模组 ZIP 内的模板与 AppData 中已经解压的 DIY 词条是两份文件，替换模组不会自动替换已解压词条。

13:49:23，外部词条在两局之间更新为 1.5.1。游戏进程中仍保留 1.4.0 的钩子，第二局触发了版本一致性保护，on_activate 失败。此时移动倍率、动作计时和动画校正的脚本控制器没有启动；定义中的被动攻速属性独立计算，可能仍被原生逻辑使用，不能将其解释为整个词条完全没有效果。

本版保留版本保护，避免同时运行不同版本的钩子。若更新已加载的词条后未重启，会显示含旧、新版本号的三语屏幕提示，每次版本变更只提示一次，日志也明确标出 hooks 与 package 版本。

## 更新和确认

1. 退出游戏，安装本版 ZIP。
2. 启动游戏，在 DIY 管理中使用「解压模板DIY词条」，将狂暴攻势外部包更新为 1.6.0。
3. 重启游戏，确认已选中狂暴攻势，再开始新任务。

预期新局日志包含：

```text
[Frenzied assault 1.6.0] move=2.00 melee=+1.00 ranged=+1.00 special=2.00 stagger=native animation=layer_clock scope=local_authority
```

出现 `animation_clock=running updated_units=...` 表示动画校正已写入至少一个单位；它不能代替实机画面、混合层与联机客户端的验证。仅看到管理器版本号，也不能证明外部词条已经更新。
